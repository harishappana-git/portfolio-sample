Why a link works locally but breaks on GitHub Pages

If your site lives at username.github.io/project/, a leading slash can send the browser outside your project.

Where the browser looks

A stylesheet link such as /style.css starts at the domain root. A local server often serves your project there, so the page looks fine. On a GitHub Pages project site, the browser asks for username.github.io/style.css, while the file lives under /project/.

Use paths relative to each page

The homepage links to style.css because the files are in the same folder. This article is inside writing/, so it uses ../style.css to go up one level. Both paths reach the same file.

Check the deployed site

Open the homepage and a nested article directly. Verify both have styling, then follow the links in both directions. If styling is missing, check the stylesheet request in the browser’s Network panel and compare its address with the file’s deployed location.
